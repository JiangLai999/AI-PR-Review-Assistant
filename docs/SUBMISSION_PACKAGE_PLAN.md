## 二、应用方案 PDF（目标 16—18 页，绝不超过 20 页）

### 推荐目录

1. **封面**（1 页）
   - 项目名称：AI PR Review Assistant
   - 项目定位：可解释、可复盘的 AI PR 代码审查工作台
   - 团队 / 作者 / 参赛信息

2. **项目背景与问题痛点**（1 页）
   - PR 审查依赖人工经验；
   - AI 代码审查容易出现幻觉、错误行号和无证据结论；
   - 传统规则工具缺乏上下文和跨文件理解；
   - 审查结果缺少历史复盘和反馈闭环。

3. **目标用户与使用场景**（1 页）
   - 个人开发者；
   - 软件研发团队；
   - 代码审查负责人；
   - 教学、开源和竞赛评测场景。

4. **需求分析与产品目标**（1 页）
   - 准确发现风险；
   - 让 AI 结论可验证；
   - 降低审查成本；
   - 支持本地运行和隐私保护；
   - CLI 与 Web 双入口。

5. **总体解决方案**（1 页）
   - 输入 GitHub PR；
   - 生成 ReviewPlan；
   - 规则 + AST + AI 分析；
   - 证据验证；
   - 跨文件影响；
   - 结果、反馈和历史复盘。

6. **系统架构图**（1 页）
   - 使用 `docs/assets/p2/project-architecture.png`；
   - 补充 CLI、Web、GitHub、DeepSeek、SQLite 的关系说明。

7. **审查流水线图**（1 页）
   - 使用 `docs/assets/p2/review-pipeline.png`；
   - 解释八个步骤和每一步的输入输出。

8. **AI 功能核心作用**（2 页）
   - ReviewPlanner：规划审查范围和风险；
   - DeepSeek：理解意图、上下文和潜在逻辑问题；
   - 结构化输出：统一 Finding Schema；
   - AI 与静态规则、AST、证据验证协同；
   - 强调 AI 不是孤立聊天，而是审查智能体的一部分。

9. **确定性分析与证据可信度**（2 页）
   - 静态安全规则；
   - Python AST；
   - Finding 文件 / 行号 / Diff 验证；
   - valid / needs_review / invalid 状态；
   - 跨文件接口影响分析。

10. **主要功能说明**（2 页）
    - CLI；
    - Web 工作台；
    - 审查计划；
    - 完整审查；
    - 离线 Demo；
    - Benchmark；
    - 历史记录；
    - 人工反馈。

11. **用户操作流程与交互指南**（2 页）
    - Web：启动服务 → 输入 PR → 生成计划 → 完整审查 → 查看证据 → 反馈 → 历史复盘；
    - CLI：doctor → demo → plan → review → history；
    - 服务未启动、Token 缺失、模型不可用时的备援流程。

12. **技术方案与开发工具**（1 页）
    - Python 3.13；
    - Click；
    - Rich；
    - Pydantic；
    - tree-sitter；
    - React + Vite；
    - GSAP；
    - SQLite；
    - GitHub API；
    - DeepSeek OpenAI-compatible API。

13. **效果、测试与准确率边界**（1 页）
    - 338 tests passed；
    - Benchmark 精选样例集结果；
    - 真实 PR 联调结果；
    - 明确说明 Benchmark 不等同于真实世界泛化准确率。

14. **应用前景与商业模式**（1 页）
    - 团队代码质量助手；
    - 企业私有化部署；
    - CI/CD 集成；
    - 开源基础版 + 企业增强版；
    - 审查质量数据和工程效能分析服务。

15. **总结与未来规划**（1 页）
    - 多语言 AST；
    - 更丰富的企业代码平台；
    - 反馈驱动的规则优化；
    - 组织级风险趋势分析。

## 三、演示视频方案（目标 4 分 30 秒，绝不超过 5 分钟）

### 视频结构

| 时间 | 内容 | 重点 |
|---|---|---|
| 0:00—0:20 | 产品定位 | 说明不是一次模型调用，而是可解释审查工作流 |
| 0:20—1:00 | Web 概览页 | 展示产品价值、八步流程、Benchmark |
| 1:00—1:45 | 离线 SQL 注入 Demo | 展示接收请求、规划、规则命中、证据有效 |
| 1:45—2:25 | ReviewPlan | 展示风险、优先文件、策略和跨文件判断 |
| 2:25—3:25 | 完整 AI 审查 | 展示 DeepSeek、进度阶段、证据验证和跨文件影响 |
| 3:25—3:55 | 结果与人工反馈 | 展示 Finding、反馈、历史记录 |
| 3:55—4:20 | CLI 备援 | 展示 doctor → demo → plan → history |
| 4:20—4:30 | 总结 | 强调本地、证据、复盘和实际价值 |

### 视频必须明确展示的智能体过程

- 接收 PR URL 或离线 Demo 请求；
- 识别 PR 意图和风险类别；
- 生成审查计划；
- 决定重点文件和分析策略；
- 协调规则、AST、DeepSeek 和跨文件分析；
- 验证 Finding 证据；
- 输出结果并写入历史；
- 接收人工反馈。

### 录制要求

- MP4；
- 总时长控制在 4 分 30 秒以内；
- 浏览器和终端文字清晰可读；
- 不出现 API Key、GitHub Token、个人路径和隐私信息；
- 准备离线 Demo 作为网络失败备援；
- 全程使用统一项目 Icon 和品牌视觉。
