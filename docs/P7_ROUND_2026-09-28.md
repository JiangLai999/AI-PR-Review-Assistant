## 二、跨槽位预算闭环（`149d4ae`）

**问题**：hybrid 审查里 local 与 remote 各持一个 `CostController`，两个槽位都只看到自己那一半开销 —— `max_cost_per_run` 与 24h 预算被按槽位数稀释（各花一半即可分别绕过）。

**关键设计**：**只共享账本，不共享 controller。**

- 新增 `CostLedger`（`run_total` + `usage_history`），`CostController.__init__` 可注入；`AIClient` 透传 `cost_ledger`。
- `HybridReviewOrchestrator` 每轮建一个账本交给两个槽位；成本按「全局总量的增量」结算，正常返回与失败分支都记账，天然不会重复计数。
- 不共用 controller 是刻意的：`_get_model_pricing()` 对未知模型（本地 qwen 等）会退回 controller 自己的价目，共用后本地调用会被按云端价计费（`local_only` 报 $0.0311 的事故即此）。

**反向用例锁死边界**：`test_shared_ledger_keeps_each_controllers_pricing` —— 本地 0 价 + 云端 3 价的组合合计必须是 3.0；若误共享 controller 会算成 6.0，测试即红。

## 三、Web 415 的 RST 陷阱（`64f5f9a`）

写端点的跨站守卫用 `Connection: close` 回 415，但请求体一个字节都没读就关闭套接字：内核直接回 RST（Windows 上 `WinError 10053`），客户端 `recv` 抛 `ConnectionAbortedError` —— 本机浏览器看到的是 **Failed to fetch** 而不是我们写的 415 JSON，测试侧表现为随机红。

修法：三层守卫的拒绝路径先限长（`MAX_BODY_BYTES`）限时（0.25s，用完恢复原 timeout）丢掉**已到达**的 body，再回包；客户端没真发时只多等一次 `recv`，绝不长挂。

复现/验证：修前 `tests/test_web_server.py` 连跑 2 次都是 79 passed / 1 failed；修后连跑 2 次 80 passed。测试同步加固为断言 415 回包能被完整读回。
